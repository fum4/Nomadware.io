# `apps/marketing` — the nomadware.io site

**What:** the public site at `nomadware.io` (canonical; `www.nomadware.io` 308s to it, `infra/terraform/vercel.tf`). One page, Astro 7, rendered on demand (for the live stats) behind Vercel's CDN cache (`s-maxage=60, stale-while-revalidate=300`), plus the on-demand `POST /api/contact` (a Vercel function), deployed by Vercel through `@astrojs/vercel`. Client JS is a handful of small vanilla `<script>` modules — no framework runtime. Package `@nomadware/marketing`.

**Depends on:** `@nomadware/site-stats` (`packages/site-stats`: the stats snapshot's shape, validator and R2 object). The Vercel project (`nomadware-io`, team `nware`, framework preset `astro`) builds it with Root Directory `apps/marketing`; those settings, and the env it runs with, are Terraform in `infra/terraform/vercel.tf`; local env comes from `infra/env/marketing.dev.env`.

**Run:** `mise run marketing:dev` (dev server, :4321) · `mise run marketing:build` (`astro check` + `astro build`, what Vercel runs) · `mise run marketing:test` (vitest, hermetic) · `mise run marketing:preview` (the production build as Vercel runs it, `vercel build`, served on :4321 with `/api/*` and the `vercel.json` routes; no Vercel login — [tools/vercel-preview](../../tools/vercel-preview/README.md)). `pre-merge` gates test + build. Vercel deploys only `master` (preview deployments are off, commits that don't touch the site are skipped: `infra/terraform/vercel.tf`), so `marketing:preview` is how you see a branch's production build. Each first renders `apps/marketing/.env` (`mise run secrets:render`, from `infra/env/marketing.dev.env`): the build needs `TURNSTILE_SITE_KEY`. On the devbox, long-running servers go through `devstack run` / `/serve`. `dev` passes `--ignore-lock`: Astro backgrounds its dev server when it detects an agent, which would detach it from its supervisor. (`astro preview` can't serve `@astrojs/vercel` output, hence the Vercel-faithful preview.)

**Conventions:**
- Server renders final content; scripts only enhance (no-JS gets every number, the full wordmark, and the contact address in place of the form).
- Background layers, bottom → top: ink + grid paper (`--grid-color`) → the **column halo** (an ink veil, `--halo-column`, down the content column at full height with soft sides; `.frame` in `global.css`) → violet glow → the hero dot field and the section bands → the **text halo** behind the hero copy (`--halo-text`, two intersected linear masks, `hero.astro`) → content. Both halos are gradients painted once: no blur, no layout, no CLS. A new busy background behind text gets a halo the same way, not text shadows.
- Colours only through `tokens.css`. `--faint` is the dimmest text colour that still passes 4.5:1 on `--ink`; go dimmer only for non-text.
- Fonts: Geist + Geist Mono, self-hosted from `@fontsource-variable/*` via Astro's font API (`astro.config.ts`), latin subset, `font-display: swap`, Geist preloaded.
- Env goes through `astro:env` (`astro.config.ts` schema) and is read only in `src/config/` (`build-info.ts`, `contact.ts`, `stats-source.ts`). Off Vercel the SHA reads `dev`. Vercel's values are Terraform (`infra/terraform/vercel.tf`); local ones are rendered (above), your overrides go in `apps/marketing/.env.local`. The build time is a build constant (`import.meta.env.BUILT_AT`, `vite.define`), never the request clock.

**Motion** (owner's call, NWARE-82). Every animation plays whatever `prefers-reduced-motion` says — headline scramble, stats count-up, wordmark, dot field (cursor scatter included), the terminal's caret and typing glow, the consent card's slide, the live dot's pulse, smooth scrolling — except the two that **flash**: the hero tags' power-on flicker and the send button's neon surge on hover. Under reduced motion those become a plain fade of `--flash-fallback-fade` (180 ms, `tokens.css`). Why those two: rapid on/off brightness is what WCAG 2.3.1 (Three Flashes) guards against, and the surge is also motion triggered by an interaction (2.3.3, Animation from Interactions); the rest is movement without flashing, kept on deliberately (2.3.3 is AAA, so this is a choice, not a failure of the AA target). The policy lives in `src/scripts/motion-policy.ts` (`flashingAllowed()`); nothing else reads the media query except the one CSS copy for the send button (`styles/contact-terminal.css`, it points back). A new flashing effect asks `flashingAllowed()` and gets a fade fallback; a new non-flashing one just plays.

**Live stats.** Every request (CDN-cached for a minute) reads `v1/stats.json` from R2, written every 5 min by the devbox (`tools/stats-publisher`, which documents what each number measures). Credential: `STATS_R2_ACCESS_KEY_ID` / `STATS_R2_SECRET_ACCESS_KEY` (read-only, set by `infra/terraform/vercel.tf`). If the read fails (no credential, timeout after 1.5 s, bad response, JSON that fails `parseStatsSnapshot`), the page renders the bundled `src/data/stats-snapshot.ts` instead. Either way "updated Xm ago" is the snapshot's real age, and past 24 h the live dot goes grey and stops pulsing. `data-stats-source` on the strip (`live` · `bundled:no-credentials` · `bundled:fetch-failed`) says which one you're seeing. To refresh the fallback, paste in `mise run stats:compute -- --dry-run`.

**Contact form** (NWARE-82). "send" posts JSON to `POST /api/contact`, which emails `contact@nomadware.io` through Resend (from `contact-form@send.nomadware.io`, reply-to the visitor). Spam: a honeypot field (`website`; filled → a fake 200, nothing sent), Cloudflare Turnstile (managed, `interaction-only`; the script loads on the form's first focus, never with the page; the token is verified server-side incl. hostname), and a per-IP limit of 5/hour **per warm function instance** — best effort, reset by cold starts; a shared counter (Vercel WAF rate-limit rule) is the upgrade if spam gets past Turnstile. Every failure reads the same to the visitor; the reason code (`contact-api.ts`) goes to the log. Env: `TURNSTILE_SITE_KEY` (public, build-time, required), `TURNSTILE_SECRET` + `TURNSTILE_HOSTNAME` + `RESEND_API_KEY` (runtime; any missing → `503 unconfigured`, logged by name). Locally the Turnstile values are Cloudflare's test keys (siteverify reports `example.com`) and there is no Resend key, so a local send ends `unconfigured`; to test delivery, put a key in `.env.local`. The real `<input>`/`<textarea>` sit invisibly over a painted copy (custom caret, fresh-character glow); they keep focus, autofill and screen-reader access. The email field is `type="text" inputmode="email"`: `type="email"` has no selection API, which the caret needs.

**Analytics.** PostHog (EU), proxied through `/ingest` so the page only talks to its own origin; loaded on first interaction or 3 s after load (never during start-up), production builds served from `nomadware.io` only (a `marketing:preview`, local or over the tailnet, never sends). Anonymous and storage-free until the visitor says "sure" in the consent banner (footer "privacy" reopens it). Custom events go through `track()` from `src/scripts/analytics/track.ts`; their names are a dashboard contract (`events.ts`). Mechanism and the consent model: [src/scripts/analytics/README.md](src/scripts/analytics/README.md).

**Extend:** a page is a file under `src/pages/` (prerendered unless it sets `export const prerender = false` like `index.astro`; an on-demand page also goes in the sitemap's `customPages`, `astro.config.ts`). A component is one `.astro` file under `src/components/`; its behaviour is a module under `src/scripts/` imported from the component's `<script>`. Formatting and lint come from the repo root (`pnpm check:format`, `pnpm check:lint`; oxfmt doesn't format `.astro`).
