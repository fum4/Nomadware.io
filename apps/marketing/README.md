# `apps/marketing` — the nomadware.io site

**What:** the public site at `nomadware.io` (canonical; `www.nomadware.io` 308s to it, `infra/terraform/vercel.tf`). One page, Astro 7, rendered on demand (for the live stats) behind Vercel's CDN cache (`s-maxage=60, stale-while-revalidate=86400`: fresh for a minute, then answered from cache for up to a day while it revalidates in the background), plus the on-demand `POST /api/contact` (a Vercel function), deployed by Vercel through `@astrojs/vercel`. Client JS is a handful of small vanilla `<script>` modules — no framework runtime. Package `@nomadware/marketing`.

**Depends on:** `@nomadware/site-stats` (`packages/site-stats`: the stats snapshot's shape, validator and R2 object). The Vercel project (`nomadware-io`, team `nware`, framework preset `astro`) builds it with Root Directory `apps/marketing`; those settings, and the env it runs with, are Terraform in `infra/terraform/vercel.tf`; local env comes from `infra/env/marketing.dev.env`.

**Run:** `mise run marketing:dev` (dev server, :4321) · `mise run marketing:build` (`astro check` + `astro build`, what Vercel runs) · `mise run marketing:test` (vitest, hermetic) · `mise run marketing:preview` (the production build as Vercel runs it, `vercel build`, served on :4321 with `/api/*` and the `vercel.json` routes; no Vercel login — [tools/vercel-preview](../../tools/vercel-preview/README.md)). `pre-merge` gates test + build. Vercel deploys only `master` (preview deployments are off, commits that don't touch the site are skipped: `infra/terraform/vercel.tf`), so `marketing:preview` is how you see a branch's production build. Each first renders `apps/marketing/.env` (`mise run secrets:render`, from `infra/env/marketing.dev.env`): the build needs `TURNSTILE_SITE_KEY`. On the devbox, long-running servers go through `devstack run` / `/serve`. `dev` passes `--ignore-lock`: Astro backgrounds its dev server when it detects an agent, which would detach it from its supervisor. (`astro preview` can't serve `@astrojs/vercel` output, hence the Vercel-faithful preview.)

**Conventions:**
- Server renders final content; scripts only enhance (no-JS gets every number, the full wordmark, and the contact address in place of the form).
- Background layers, bottom → top: ink + grid paper (`--grid-color`; on mouse-first desktops redrawn by `scripts/grid-warp.ts` on a fixed canvas that bends it toward the cursor, pixel-identical at rest, the CSS grid being first paint and the touch / no-JS fallback) → the **column halo** (an ink veil, `--halo-column`, down the content column at full height with soft sides; `.frame` in `global.css`) → violet glow → the hero dot field and the section bands → the **text halo** behind the hero copy (`--halo-text`, two intersected linear masks, `hero.astro`) → content. Both halos are gradients painted once: no blur, no layout, no CLS. A new busy background behind text gets a halo the same way, not text shadows.
- Colours only through `tokens.css`. `--faint` is the dimmest text colour that still passes 4.5:1 on `--ink`; go dimmer only for non-text.
- Fonts: Geist + Geist Mono, self-hosted from `@fontsource-variable/*` via Astro's font API (`astro.config.ts`), latin subset, `font-display: swap`, Geist preloaded.
- Env goes through `astro:env` (`astro.config.ts` schema) and is read only in `src/config/` (`build-info.ts`, `contact.ts`, `stats-source.ts`). Off Vercel the SHA reads `dev`. Vercel's values are Terraform (`infra/terraform/vercel.tf`); local ones are rendered (above), your overrides go in `apps/marketing/.env.local`. The build time is a build constant (`import.meta.env.BUILT_AT`, `vite.define`), never the request clock.

**Motion** (owner's call, NWARE-82). Every animation plays whatever `prefers-reduced-motion` says — nothing on the site reads it: headline scramble, the hero tags' power-on flicker, the stats card's draw and count-up, wordmark, dot field (cursor gather, settle, release and the black hole included), the terminal's caret, typing glow and the send button's neon surge, the consent card's slide, the live dot's pulse, smooth scrolling. The two flashing effects (tags, send button) are small text, far below WCAG 2.3.1's flash-area threshold; 2.3.3 (Animation from Interactions) is AAA, so playing them is a choice, not a failure of the AA target.

**Live stats.** Every request (CDN-cached for a minute) reads `v1/stats.json` from R2, written every 5 min by the devbox (`tools/stats-publisher`, which documents what each number measures). Credential: `STATS_R2_ACCESS_KEY_ID` / `STATS_R2_SECRET_ACCESS_KEY` (read-only, set by `infra/terraform/vercel.tf`). If the read fails (no credential, timeout after 0.8 s, bad response, JSON that fails `parseStatsSnapshot`), the page renders the bundled `src/data/stats-snapshot.json` instead (so does local dev, which has no read credential). Either way "updated Xm ago" is the snapshot's real age, and past 24 h the live dot goes grey and stops pulsing. `data-stats-source` on the card (`live` · `bundled:no-credentials` · `bundled:fetch-failed`) says which one you're seeing. To refresh the fallback, paste the output of `mise run stats:compute -- --dry-run` into that file.

**Stats card** (`components/stats-card.astro`, NWARE-82). The window's agent-minutes per bucket as a seismograph line (`stats-chart.astro`; 7d: 2 h buckets, 30d: 6 h, from the snapshot's `series`, `@nomadware/site-stats`) (runs of empty buckets as a faint dotted baseline, so an idle stretch reads as quiet), a warm dot on the line at each bucket whose gates caught issues (6 px for one issue, its area growing with the count up to ≈ 9.5 px across, cut out of the line by a ring of the plot's colour), a legend of six numbers underneath and a 7d/30d toggle. A range's first showing (30d once the card is in view, 7d on its first toggle) draws its line left to right over 3 s as one stroke, and the numbers count in step with it: every one starts at 0 and adds a bucket's share as the pen reaches its point (a quiet stretch holds, a spike climbs fast; the first bucket, with whatever the window counts before it, ramps in as the pen draws the first segment), a caught dot pops as the issues counter steps (and one warm ring pulses off it, global.css `ring-pulse`, the live dot's own pulse; pulses queue at least 120 ms apart, tightened so a queue drains within 1.5 s: `MARKER_PULSE`, `scripts/marker-pulse.ts`), and every number lands on its total as the line ends (`TRACE_DRAW` in `constants.ts`; one Web Animation is the clock, `scripts/trace-draw.ts`). After that a toggle just swaps the line, recounts (`COUNT_UP_TOGGLE_MS`) and ripples its caught dots' pulses left to right (a toggle drops the queue of the range it leaves); a toggle mid-draw drops it, and that range draws again next time. Without JS the line, dots and final numbers simply show. Pointing at the chart (mouse hover, or a tap / horizontal drag on touch: `touch-action: pan-y`, so a vertical swipe still scrolls) snaps a dot and a guide line to the nearest bucket and shows a chip just above the plot, centred on the guide, growing upward over the card's header and past the card if need be (never over the trace; kept 8 px inside the viewport, and below the plot when there is no room above): the bucket's time in the visitor's zone, its agent work and merged PRs, their lines added / deleted ("+12,079 −2,110"), then under a hairline the issues caught (warm) and the gate that caught them (dim: "5 issues caught · 3 at push, 2 at merge"), their kinds when known ("3 tests, 2 types") and how long they took to fix once every one is ("✓ fixed in 1h 58m") (rows with nothing to say hide). At rest there is no chip; it goes when the mouse leaves, on a tap elsewhere, and on a toggle. A snapshot without a series (an older publisher) renders the card without the chart; its numbers count up on the same clock.

**Contact form** (NWARE-82). "send" posts JSON to `POST /api/contact`, which emails `contact@nomadware.io` through Resend (from `contact-form@send.nomadware.io`, reply-to the visitor). Spam: a honeypot field (`website`; filled → a fake 200, nothing sent), Cloudflare Turnstile (managed, `interaction-only`; the script loads on the form's first focus, never with the page; the token is verified server-side incl. hostname), and a per-IP limit of 5/hour **per warm function instance** — best effort, reset by cold starts; a shared counter (Vercel WAF rate-limit rule) is the upgrade if spam gets past Turnstile. Every failure reads the same to the visitor; the reason code (`contact-api.ts`) goes to the log. Env: `TURNSTILE_SITE_KEY` (public, build-time, required), `TURNSTILE_SECRET` + `TURNSTILE_HOSTNAME` + `RESEND_API_KEY` (runtime; any missing → `503 unconfigured`, logged by name). Locally the Turnstile values are Cloudflare's test keys (siteverify reports `example.com`) and there is no Resend key, so a local send ends `unconfigured`; to test delivery, put a key in `.env.local`. The real `<input>`/`<textarea>` sit invisibly over a painted copy (custom caret, fresh-character glow); they keep focus, autofill and screen-reader access. The email field is `type="text" inputmode="email"`: `type="email"` has no selection API, which the caret needs.

**Analytics.** PostHog (EU), proxied through `/ingest` so the page only talks to its own origin; loaded on first interaction or 3 s after load (never during start-up), production builds served from `nomadware.io` only (a `marketing:preview`, local or over the tailnet, never sends). Anonymous and storage-free until the visitor says "sure" in the consent banner (footer "privacy" reopens it). Custom events go through `track()` from `src/scripts/analytics/track.ts`; their names are a dashboard contract (`events.ts`). Mechanism and the consent model: [src/scripts/analytics/README.md](src/scripts/analytics/README.md).

**Extend:** a page is a file under `src/pages/` (prerendered unless it sets `export const prerender = false` like `index.astro`; an on-demand page also goes in the sitemap's `customPages`, `astro.config.ts`). A component is one `.astro` file under `src/components/`; its behaviour is a module under `src/scripts/` imported from the component's `<script>`. Formatting and lint come from the repo root (`pnpm check:format`, `pnpm check:lint`; oxfmt doesn't format `.astro`).
